# Лабораторная №1 — консольная RAG-система

Node.js 22+, JavaScript ES Modules, Ollama (`qwen3:1.7b` и `nomic-embed-text`), Qdrant 1.15+. Приложение не использует Docker, фреймворки RAG и веб-интерфейс. Уже установленный Qdrant можно запускать любым удобным способом, в том числе существующим контейнером.

## Запуск в Visual Studio 2026

Откройте **Файл → Открыть → Папка** и выберите эту папку. Откройте терминал PowerShell в корне проекта. Файл `.sln` для консольного Node.js-приложения не требуется.

1. Проверьте Node.js: `node --version` (22 или новее).
2. Запустите Ollama. Если моделей ещё нет, выполните `ollama pull qwen3:1.7b` и `ollama pull nomic-embed-text`. Проверка: `ollama list`. Программа сама модели не скачивает.
3. Запустите **уже установленный Qdrant**. На этом компьютере найден контейнер `pad11-qdrant-1`: его можно запустить в Docker Desktop или командой `docker start pad11-qdrant-1`. Это внешняя установленная база; проект не создаёт контейнеров. Проверка: `Invoke-RestMethod http://localhost:6333/`.
4. Выполните команды:

```powershell
npm ci
npm run grab
npm run index
npm run ask -- "Почему строки Python нельзя изменять?"
npm run evaluate
```

`npm run ask` без аргумента предложит ввести вопрос. `npm test` запускает короткие проверки без внешних сервисов. При ошибке команды возвращают ненулевой код. Оставляйте Ollama и Qdrant запущенными во время работы.

## Где менять параметры

Для работы через консольное меню выполните `npm start`. В нём доступны все настройки (включая вложенные параметры prompt, генерации и экспериментов), сбор страниц, индексация, вопросы и оценка. Выбор — номером пункта, `0` — назад/выход. Переключатели принимают `да/нет`, списки — JSON, например `[4,7,26]` или `["baseline","fixed-1200"]`; `[]` выбирает все вопросы/варианты. В списке настроек вариантов можно редактировать каждый вариант или добавить новый через `a`.

При каждом выборе «Запустить эксперименты» меню автоматически выбирает **12 разных вопросов: 10 с ответом и 2 без ответа**. Вопросы берутся случайно из `experiments/questions.json`; тип определяется наличием ожидаемых источников. Числа и переключатель находятся в `evaluation.randomQuestions` в том же `config.js`. Выбранные номера сохраняются в `evaluation.questionIds` и показываются перед подтверждением запуска. Повторные выборки могут частично совпадать. Для ручного выбора выключите `randomQuestions.enabled`. Обычная команда `npm run evaluate` использует уже сохранённые номера.

Каждое принятое изменение сразу сохраняется в **том же `src/config.js`** и действует в текущем меню. Файл при сохранении форматируется автоматически, комментарии заменяются общей строкой. Не редактируйте файл вручную одновременно с открытым меню. После смены источника выполните сбор и индексацию, после смены chunking/embedding — индексацию; при смене настроек поиска или генерации можно сразу задавать вопрос. Старые коллекции Qdrant меню не удаляет. Обычные npm-команды также остаются доступны.

**Только `src/config.js`** — источник, глубина обхода, лимиты, задержки, модели, адреса сервисов, chunking, поиск, reranking, тексты prompt, режимы генерации и список экспериментов. `.env` не требуется: второго слоя настроек нет.

```js
sourceUrl: 'https://docs.python.org/3/tutorial/',
maxDepth: 1,
restrictToSourcePath: true,
```

Это стартовая страница и страницы в пределах одного перехода по ссылке, только внутри `/3/tutorial/`. Якоря и query-параметры удаляются: такие варианты URL не создают отдельные документы. Поэтому сайты, где разные документы задаются исключительно query-параметрами, не поддерживаются. Для сайта с другим обычным HTML достаточно сменить `sourceUrl`; ограничение каталога вычисляется из него. `restrictToSourcePath: false` разрешает весь тот же origin. Для URL файла каталогом считается его родительская директория. После смены источника выполните `grab`, затем `index`; для оценки подготовьте вопросы по новому корпусу.

`maxPages` ограничивает число запросов страниц за запуск, включая ошибки и перенаправления. `crawlDelay` задаётся в миллисекундах; задержка robots.txt может её увеличить. Запреты robots.txt соблюдаются, при ошибке чтения robots.txt обход отменяется; HTTP 404 означает отсутствие правил. Перенаправления проверяются по границам сайта и robots.txt. Авторизация, CAPTCHA, JavaScript-рендеринг и обход блокировок не поддерживаются.

## Обработка и индекс

`grabber.js` собирает HTML обычным fetch, извлекает заголовок, URL и ссылки. `processing.js` удаляет скрипты, стили и элементы навигации, выбирает `main`, `role=main`, `article` или `body`. Это общий алгоритм, без селекторов Python Tutorial. На необычной вёрстке возможно попадание постороннего текста.

Документы и хеши содержимого сохраняются в `data/documents.json`. Повторный запуск обновляет новые/изменённые документы, неизменённые не дублируются. Временно недоступные ранее собранные страницы сохраняются; явно полученные 404/410 удаляются. Полная синхронизация удалённых ссылок на сайте не предусмотрена.

Chunking: `fixed` — неперекрывающиеся фрагменты; `overlap` — фрагменты с перекрытием. Размер и перекрытие измеряются символами Unicode, не токенами. Слова и предложения могут разделяться на границе фрагмента. Для `overlap` необходимо `0 <= chunkOverlap < chunkSize`.

Идентификаторы документов и chunks стабильны. Индексатор создаёт коллекцию Qdrant с Cosine, сохраняет текст и metadata, удаляет старые chunks изменённого документа и записывает новые. Локальный JSON-манифест отмечает документ только после успешной записи; после сбоя повторите `index`. Неизменённые документы повторно не векторизуются. Не запускайте одновременно несколько индексаций/экспериментов.

Имя коллекции: `collectionName_<хеш>`. Хеш включает источник, embedding-модель и её digest, стратегию и параметры chunking. Несовместимые индексы хранятся отдельно; старая коллекция не удаляется автоматически. Возврат к уже проверенной конфигурации переиспользует её индекс. После изменения модели, chunking или документов выполните `npm run index`.

`embeddings.js` обращается к Ollama `/api/embed` с `truncate: false`: слишком большой фрагмент вызывает явную ошибку, а не скрытое обрезание. При такой ошибке уменьшите `chunkSize`.

## Поиск и ответы

Qdrant возвращает `topK` ближайших фрагментов, прошедших `similarityThreshold` (Cosine score, не вероятность). Одинаковые тексты удаляются. Отдельная функция `rerank` в `retrieval.js` пересортировывает найденные фрагменты по взвешенной сумме векторного score и доли слов вопроса, встречающихся в тексте/заголовке. Вес задаёт `rerankerWeight`, переключатель — `rerankerEnabled`. Это простая эвристика: она не понимает синонимы и перевод, поэтому для русских вопросов к английскому корпусу её польза ограничена. Новые кандидаты reranker не ищет.

Модель получает только найденный контекст и инструкцию не добавлять внешние знания. Ответ запрашивается как JSON с признаком наличия ответа и номерами подтверждающих фрагментов. URL берутся из metadata, а не из текста модели. При пустом поиске, отказе модели или некорректных ссылках выводится сообщение об отсутствии информации.

Эти ограничения не доказывают достоверность каждого предложения маленькой LLM: возможна ошибочная интерпретация контекста. Проверяйте поддержку фактов по показанным источникам и проводите ручную оценку. Это часть эксперимента, а не автоматическая гарантия качества.

## Эксперименты

`experiments/questions.json` содержит 30 русскоязычных вопросов: 25 с ожидаемыми URL и подтверждающим фрагментом, 5 без ответа в корпусе. Положительные примеры сверяются с фактически сохранённым текстом перед оценкой. Это тестовые данные, не второе место настройки параметров. При смене сайта вопросы нужно заменить.

В `config.js → evaluation.variants` перечислены отдельные отклонения от базовой конфигурации: две стратегии chunking, размеры/перекрытия, topK, пороги, reranker, два prompt и два режима одной LLM (`temperature=0` и `0.6`, одинаковый seed). Это сравнения с базовым вариантом, а не полный перебор комбинаций. Чтобы сравнить другую пару комбинаций, измените список там же. Для второй embedding-модели вручную скачайте её и добавьте вариант с `embeddingModel`; автоматической загрузки нет.

По умолчанию для короткой проверки выбраны **6 вопросов и baseline**: `evaluation.questionIds` и `evaluation.variantNames` в `config.js`. Пять вопросов проверяют разные главы, шестой не имеет ответа в корпусе. Установите оба списка в `[]`, чтобы запустить все 30 вопросов и все варианты. Данные вопросов остаются в `questions.json`.

`npm run evaluate` индексирует необходимые варианты и сохраняет результаты после каждого вопроса в `experiments/results-<дата>.json`: настройки, corpus hashes, коллекция, найденные фрагменты и score, ответы/источники, время и ошибки. Полная матрица — 360 ответов — может занять значительное время. Для проверки только поиска установите `evaluation.generateAnswers: false`.

Метрики считаются **на уровне документов**, а не отдельных chunks:

- Hit Rate@K — доля вопросов с хотя бы одним ожидаемым URL среди результатов.
- MRR — среднее `1 / ранг` первого результата с ожидаемым URL; при отсутствии — 0.
- `noAnswerAccuracy` — доля корректных отказов среди выбранных вопросов без ответа; только при включённой генерации.

Вопросы без ответа исключены из Hit Rate и MRR. Ошибки указаны отдельно, `answerableEvaluated` показывает фактический знаменатель. Вручную заполните `manualQuality`: 0 — неверно/неподтверждённо, 1 — частично верно, 2 — полно и подтверждено; замечания — в `manualNotes`. Для отрицательного вопроса правильный отказ получает 2. Ручные оценки автоматически не подставляются.

## Файлы

- `src/config.js` — единые настройки.
- `src/grabber.js`, `processing.js` — обход, локальное хранение и chunking.
- `src/embeddings.js`, `database.js` — Ollama и Qdrant.
- `src/retrieval.js`, `generation.js` — поиск, reranking и ответы.
- `src/evaluation.js`, `index.js` — эксперименты и CLI.
- `experiments/questions.json` — тестовые вопросы.
- `test/core.test.js`, `test/indexing.test.js` — автономные проверки обработки и обновления индекса, включая восстановление после сбоя.
- `package.json`, `package-lock.json`, `.gitignore` — запуск и зависимости.

Данные, локальные индексы, результаты и `node_modules` не включаются в Git. Результаты не заполняются выдуманными значениями.

Документация сервисов: [Ollama embeddings](https://docs.ollama.com/api/embed), [Qdrant Query API](https://api.qdrant.tech/api-reference/search/query-points), [официальные сборки Qdrant](https://github.com/qdrant/qdrant/releases).
