# Лабораторная №1: RAG

Node.js 22+, Ollama (`qwen3:1.7b`, `nomic-embed-text`) и Qdrant 1.15+.

## Запуск

В Visual Studio откройте папку проекта и терминал PowerShell. Запустите Ollama и Qdrant. Для существующего контейнера:

```powershell
docker start pad11-qdrant-1
```

Если моделей нет:

```powershell
ollama pull qwen3:1.7b
ollama pull nomic-embed-text
```

Установка зависимостей и запуск меню:

```powershell
npm ci
npm start
```

В меню доступны настройки, сбор страниц, индексация, вопросы и эксперименты. `0` — назад или выход. Переключатели принимают `да/нет`, списки — JSON: `[4,7,26]` или `["baseline","fixed-1200"]`.

Команды без меню:

```powershell
npm run grab
npm run index
npm run ask -- "Для чего используется range()?"
npm run evaluate
npm test
```

Ollama и Qdrant должны работать во время индексации, поиска и оценки.

## Настройки

Все параметры находятся в `src/config.js`. Меню сохраняет изменения в этот же файл, переформатируя его без комментариев. Не редактируйте файл вручную одновременно с открытым меню.

| Параметр | Назначение |
| --- | --- |
| `sourceUrl` | Начальная страница |
| `maxDepth`, `maxPages`, `crawlDelay` | Глубина обхода, лимит запросов, задержка в мс |
| `restrictToSourcePath` | Ограничение каталогом источника |
| `chunkStrategy` | `fixed` — без перекрытия, `overlap` — с перекрытием |
| `chunkSize`, `chunkOverlap` | Размер и перекрытие в символах; перекрытие меньше размера |
| `embeddingModel`, `generationModel` | Модели Ollama |
| `ollamaUrl`, `qdrantUrl` | Адреса сервисов |
| `collectionName` | Префикс коллекций Qdrant |
| `topK`, `similarityThreshold` | Количество результатов и минимальный Cosine score |
| `rerankerEnabled`, `rerankerWeight` | Переранжирование и его вес |
| `promptVariant` | `strict` или `concise`; тексты — в `prompts` |
| `generationMode` | `precise` или `creative`; параметры — в `generationModes` |

После изменения источника выполните `grab`, затем `index`. После изменения chunking или embedding-модели достаточно `index`. Настройки поиска, prompt и генерации применяются без переиндексации.

## Документы и индекс

По умолчанию собирается Python Tutorial: начальная страница и ссылки в пределах одного перехода внутри `/3/tutorial/`. Краулер учитывает robots.txt. Якоря и query-параметры удаляются; сайты с документами только в query-параметрах и страницы с JavaScript-рендерингом не поддерживаются.

Документы сохраняются в `data/documents.json`. Изменения определяются по хешу текста и заголовка. Временно недоступные документы сохраняются, получившие 404/410 удаляются. Исчезновение ссылки со страницы само по себе не удаляет документ.

HTML очищается от скриптов, стилей и навигации. Основной текст извлекается из `main`, `role=main`, `article` или `body`. Фрагменты имеют фиксированную длину и могут разрезать слова и предложения.

Неизменённые документы повторно не векторизуются. У изменённого документа старые chunks удаляются из Qdrant и заменяются новыми. После сбоя повторите `index`. Не запускайте индексацию и эксперименты одновременно.

Коллекция называется `collectionName_<хеш>`. Хеш учитывает источник, embedding-модель с её digest и параметры chunking. При их смене создаётся отдельная коллекция. Старые коллекции остаются в Qdrant, но текущий поиск их не использует. Удаление локальной папки `data` не очищает Qdrant.

## Поиск

Qdrant возвращает ближайшие chunks с учётом `topK` и порога сходства. Одинаковые тексты удаляются. Reranker объединяет векторный score с долей слов вопроса, найденных в тексте и заголовке. Он не учитывает синонимы и перевод, поэтому для русских вопросов к английскому тексту его польза ограничена.

Модель получает найденный контекст и возвращает ответ с номерами источников. URL берутся из metadata документов. Если контекста нет или модель отказывается отвечать, выводится сообщение об отсутствии информации. Поддержку фактов источниками нужно проверять при ручной оценке.

## Эксперименты

В `experiments/questions.json` находятся 30 вопросов: 25 с ожидаемыми источниками и 5 без ответа в корпусе. При смене сайта замените вопросы. Перед оценкой подтверждающие фрагменты сверяются с собранными документами.

При запуске оценки из меню случайно выбираются 12 разных вопросов: 10 с ответом и 2 без ответа. Настройки — `evaluation.randomQuestions`. Выбранные номера сохраняются в `evaluation.questionIds` и показываются перед подтверждением. Для ручного выбора выключите `randomQuestions.enabled`.

`npm run evaluate` использует сохранённые `questionIds`. Пустой список означает все вопросы. `evaluation.variantNames` задаёт варианты из `evaluation.variants`; пустой список запускает все варианты. `generateAnswers: false` отключает генерацию и оставляет только проверку поиска.

Готовые варианты сравнивают chunking, размеры и перекрытия, topK, пороги, reranker, prompt и два режима генерации. Для второй embedding-модели установите её через `ollama pull` и добавьте вариант с полем `embeddingModel`.

Результаты сохраняются после каждого вопроса в `experiments/results-<дата>.json`: настройки, хеши документов, найденные chunks, ответы, источники, время и ошибки.

Метрики:

- Hit Rate@K — доля вопросов с ожидаемым URL среди результатов.
- MRR — среднее обратного ранга первого результата с ожидаемым URL.
- `noAnswerAccuracy` — доля правильных отказов на вопросах без ответа.

Вопросы без ответа исключены из Hit Rate и MRR. Ошибки учитываются отдельно. Для ручной оценки заполните `manualQuality`: 0 — неверно, 1 — частично верно, 2 — полно и подтверждено. Комментарий к оценке — `manualNotes`.

`data`, результаты экспериментов и `node_modules` не включаются в Git.
